# GPU and software rendering backends

Buffer import, scene drawing and presentation are separate parts of the rendering path. A software renderer in Chromium does not establish that a particular Wayland server path can import and present every client buffer. [source] ([Software renderer](https://github.com/chromium/chromium/blob/9261fd0a595ac4964ea84e6bd4a025c1173a2ffa/components/viz/service/display/software_renderer.h#L29))

## Behavior

- Drawing a frame, allocating or importing its resources, and presenting it are separate operations. [source] ([Renderer interfaces](https://github.com/chromium/chromium/blob/9261fd0a595ac4964ea84e6bd4a025c1173a2ffa/components/viz/service/display/software_renderer.h#L31))
- Backdrop sampling and filter support are distinct from hardware overlay eligibility. [source] ([Software filter hooks](https://github.com/chromium/chromium/blob/9261fd0a595ac4964ea84e6bd4a025c1173a2ffa/components/viz/service/display/software_renderer.h#L96))

## How donors do it

| Donor @ pin | Mechanism | Notable behavior or limit | Link |
|---|---|---|---|
| Chromium Viz @ 150 | `SoftwareRenderer` draws render passes using software resources | Its existence is separate from native client buffer import and output backend selection | [Software renderer](https://github.com/chromium/chromium/blob/9261fd0a595ac4964ea84e6bd4a025c1173a2ffa/components/viz/service/display/software_renderer.h#L29) |
| Exo @ engine pin · chromeos-gated | Client-buffer import requests a RasterContextProvider | The function returns no resource when that provider is unavailable | [Import requirement](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/components/exo/buffer.cc#L676) |

- Chromium’s child-surface layer [emits a surface quad for a valid range, or a solid background quad otherwise](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/cc/layers/surface_layer_impl.cc#L195). Its [draw-visibility callback](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/cc/layers/surface_layer_impl.cc#L168) and activation deadlines are separate state. This describes scene embedding and readiness; backdrop sampling and physical presentation retain their own evidence boundaries. [source]

- The ordinary child-surface merge path requires [near-unit quad opacity and permission to merge](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/components/viz/service/display/surface_aggregator.cc#L645), followed by [transform, mask and capture checks](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/components/viz/service/display/surface_aggregator.cc#L914). Capture can retain an intermediate pass; [required-overlay handling](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/components/viz/service/display/surface_aggregator.cc#L1044) has a separate duplication path. A render pass is a drawing unit, distinct from a display frame. [source]

- Generic Aura-tree occlusion and platform-native host tracking are distinct mechanisms. The [native-host shim](https://github.com/chromium/chromium/blob/2493812cc0621330895498ea437bde415944c203/ui/aura/native_window_occlusion_tracker.cc#L18) delegates to Windows tracking only on Windows; its non-Windows enable and disable bodies are empty and its always-enabled query returns false. This qualifies the platform mechanism separately from the generic tree algorithm. [source]
